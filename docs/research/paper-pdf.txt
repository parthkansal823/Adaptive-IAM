Abstract—Traditional Identity and Access Management (IAM)
systems use static rules that remains same regardless of context.
For example, a user who logs in from a recognized device at a
normal hour goes through the same authentication process as
someone logging in from an unfamiliar machine from a foreign
country at an unusual time. With the known vulnerabilities of
centralized credential storage, this leaves organizations exposed
to credential theft, insider misuse, and unauthorized access on
a scale that static defenses are never meant to address. This
paper propose an adaptive IAM framework which follow Zero
Trust principles. This framework integrates machine learning
based risk scoring, large language model(LLM) to assist au-
thorization, natural language processing to validate requests,
and blockchain to make tamper proof audit logging. During
authentication, the system computes risk score from contextual
and behavioral features in real time, then applies adaptive
security measures. During authorization, the system evaluates
user provided justifications, routing uncertain requests to human
reviewers selected by an LLM based on organizational context.
All events are immutably recorded on a blockchain and smart
contracts which let us enforce time limited access grants that auto
revoke upon expiry. The expected performance analysis, based
on benchmarks from comparable published systems, projects to
be 85–92% accuracy in risk scoring, latency of less than 200
ms, and 83–89% accuracy in NLP classification. To the best of
our knowledge, no existing system brings adaptive risk scoring,
NLP based request validation, LLM assisted human in the loop
governance, and blockchain audit logging in a single unified IAM
framework together.

I. INTRODUCTION
There is a recurring pattern in recent cyber incidents that de-
serves attention. The attackers obtain valid credentials through
phishing, credential stuffing, or from a prior breach. The target
organization’s authentication mechanism has no way of telling
that user logginf into the system is not real. The correct
password was entered, access was granted, and no further
verification is performed [1].
This outcome reflects an fundamental weakness to static
authentication. The mechanism poses one question: Does the
requester possess the correct secret? If the answer is yes, the
system grants access. There is no further evaluation of whether
the login attempt matches the user’s established patterns, no
consideration of geographic or device anomalies, and system
have no path to invoke suspicious but credential valid sessions
to additional verification [1], [3]. The system was built for a
threat landscape that has since changed beyond recognition.
Authorization mechanisms suffer with parallel problem.
Access permissions in most of the deployed systems are bound
to role definitions that may not been revisited for months or
years. When an employee needs temporary access to a resource
outside their scope, like, an marketing analyst needs a financial
report of a client, this process generally involves a manual
request which gives an uncertain waiting period and also there
is an probability that the temporary access will persist beyond
its intended duration because revoking the access depends on
someone remembering to revoke it [2].
Centralized credential storage worsens both of these issues.
A single database holds identity data for all users in an
organization. Thus, this system is the highest valuable target
for the attacker. If attackers compromises it, the entire user
data is exposed. In recent years this was the main reason for
the data breaches [4], [5].
These observations clearly suggest a requirement for a
next generation authentication and authorization system. This
system should compute the risk in real time with dynamic
rules. The system should calibrate authentication challenges
according to assessed risk level. The system should bring
intelligent evaluation to authorization decisions that exceed
the capacity of simple role based checks. It should maintain
an audit trail resistant to post hoc modification. And it should
accomplish all of this without burdening legitimate users with
excessive friction, since friction drives workaround behavior
that undermines security [6].
The framework proposed in the paper addresses these re-
quirements by integrating three complementary technologies.
Machine learning models analyze behavioral and contextual
features to produce real-time risk scores. Large language
models provide the contextual reasoning needed to select ap-
propriate human reviewers for ambiguous authorization deci-
sions and to evaluate natural language justifications for access
requests. Blockchain technology provides an append only,
cryptographically chained ledger that records every event,
access decision, and vote [5], [7].
It should be noted that the framework presented here is a
proposed design. We describe the architecture, methodology,
and expected performance characteristics derived from pub-
lished benchmarks of comparable individual components. Full-
scale implementation and empirical validation on production

justified because each component – ML risk scoring, NLP

II. RELATEDWORKS
A. Risk-Based Authentication
Risk based authentication replaces the uniform challenge
model with a score driven approach. Contextual signals from
each login attempt are feeded into a classifier and the resulting
risk score determines the level of verification to be put [1], [3].
Wiefling et al. conducted an study on this topic where he
analyzed 31 million login events gathered from 3.3 million
users in the duration of twelve months. The results demon-
strated that machine learning optimization of risk parameters
yields measurable improvements in the security usability trade
off. They also released a synthesized login dataset that is taken
as the standard benchmark for the research community [3], [8].
Picard and Pierre implemented reinforcement learning ap-
proach in RLAuth, where the agent dynamically selects au-
thentication challenges based on contextual features. On the
CRAWDAD Telefonica smartphone dataset, they achieved a
geometric mean accuracy of 92.6%, which was more from
conventional classifiers [9]. Fereidouni et al. proposed F-
RBA (federated learning framework). There model trains risk
models locally on user devices which help preserving the users
data privacy while achieving improved true positive rates over
traditional anomaly detection methods [10].
B. Continuous and Behavioral Authentication
Continuous authentication extends identity verification be-
yond the login event to cover entire sessions. Baig and
Eskeland provide a comprehensive survey covering keystroke
dynamics, mouse movement analysis, and sensor-based mobile
biometrics [11]. Frank et al. demonstrated with Touchalytics
that touchscreen interaction patterns carry sufficient identity
signal to distinguish between users [12]. These methods offer
a natural advantage to risk based authentication, though the
tension between security benefits and user privacy remains a
central challenge.
C. Zero Trust and Trust Scoring
Zero Trust, formulated by Kindervag in 2010 and formal-
ized by NIST in Special Publication 800-207, works on the
principle that no user or device should receive implicit trust
regardless of network location [7], [13]. Wang et al. applied
this philosophy to Internet of Vehicles environments through
AU-ZTAC, computing dynamic trust scores from user behavior
and various attributes [14]. Google’s BeyondCorp initiative
demonstrated the viability of perimeterless enterprise security
at scale [15].
D. Blockchain-Based Access Control
Blockchain addresses the log integrity problem that plagues
centralized databases. Cryptographic hash chaining ensures
that any modification to a previous log entry invalidates all
subsequent entries. Hu et al. built N-Accesses on Ethereum,
using smart contract to enforce time limited access with
immutable event logging [16]. Tawfik et al. developed
ACHealthChain on Hyperledger Fabric, which achieved ap-
prox 19.7% throughput improvement and 87% reduction in
latency compared to earlier blockchain based access control
systems [18]. Yaqub et al. applied blockchain to GDPR-
compliant healthcare consent management [17].
E. LLMs in Access Control
Zisad proposed LLMAC, a framework unifying RBAC,
ABAC, and DAC under a single LLM, achieving 98.5%
accuracy on synthetic policy scenarios while generating human
readable justifications for each decision [19]. The interpretabil-
ity dimension is significant given that opacity in automated
security decisions remains a known barrier to enterprise adop-
tion.
F . Research Gaps
Each surveyed thread addresses a subset of IAM chal-
lenges, but none delivers the complete picture. RBA re-
search terminates at the login event and does not address
what happens when an authenticated user requests access
to a resource outside their normal permissions. Blockchain
based system provide strong integrity for audit logs, yet
they rely on static smart contract rules and do not provide
any form of adaptive, context aware decision making. LLM
based access control looks promising in early evaluations
but largely remains theoretical and has not been integrated
into the functioning authentication and authorization pipeline
with real time risk assessment. Also, none of the systems
address the authorization justification problem. The fact that
most organizations collect free text reasons for access requests
but never analyzed them programmatically. This represents a
significant missed opportunity for catching social engineering
attempts and policy violations at the point of request rather
than after the damage is done.
No published system, to our knowledge, combines adap-
tive ML based risk scoring, NLP driven request justification
validation, LLM assisted human in the loop voter selection,
and blockchain based immutable audit logging within a single
unified framework. Table I summarizes these capability gaps
across the surveyed systems. This gap constitutes the primary
motivation for the present work.

III. PROPOSEDMETHODOLOGY
A. System Overview
The framework is made by two interconnected pipelines.
The authentication pipeline computes dynamic risk score from
contextual and behavioral features in real time and apply
security challenges based on the assessed risk tier. The autho-
rization pipeline evaluates resource access requests through
NLP based analysis and when justified it routes decisions
to human reviewers who are intelligently selected by LLM.
Both pipelines share a common blockchain audit layer that
maintains an immutable record of every event.
B. Machine Learning-Based Risk Scoring
1) Feature Engineering:The risk model ingests features
organized into five categories:
•User Context Parameters:Login time, day of week,
IP address, geographic location (derived from IP), device
type, operating system and browser.
•Behavioral Parameters:Average login hours, standard
deviation from that average, login frequency across con-
figurable time windows, count of recent failed attempts,
typical session duration, and optionally keystroke timing
as a soft biometric.
•Device and Network Trust:Whether the device and
IP address have been seen before, VPN or proxy usage
flagging and device switching frequency over a rolling
one week window.
•Historical Risk Parameters:Prior risk scores, cumu-
lative suspicious activity count, time elapsed since last
login, account age, and the user’s organizational role.
•Access Request Parameters:Resource sensitivity clas-
sification and the NLP assessed validity of the user-
stated justification (applicable during authorization re-
quests only).
2) Risk Score Computation:LetX={x 1,x 2,...,x n}
denote the feature vector for a given login attempt. The trained
model computes a scalar risk scoreS=f(X)∈[0,1],
interpreted as the estimated probabilityP(suspicious|X).

3) Adaptive Authentication Mechanism:Low-risk logins

credentials are correct. In this case it strongly suggests that

redirects such sessions into a honeypot environment contain-

interface and file structure, but all data inside is fabricated.

to actual systems, and sessions is limit to 30 to 60 minutes.
Everything the attacker does inside the honeypot is been
recorded such as pages visited, files opened, search queries,
commands executed. This provides threat intelligence about
attacker objectives and methods that informs better placement
of real security controls [23].

C. NLP-Based Request Justification Validation
A notable weakness in current authorization workflows is
that access request justifications is typically collected as free
text input which are recorded but rarely evaluated through a
code/program. The proposed framework addresses this through
a two-tier NLP classification pipeline.
The preprocessing stage applies tokenization, stop word
removal, and lemmatization using spaCy. The cleaned text
is converted to a numerical feature representation via TF-
IDF vectorization with a vocabulary size capped to 5,000
features. The primary classifier is a multinomial naive bayes
model, selected for its computational efficiency and estab-
lished effectiveness in text classification. For cases where the
primary model’s probability falls below a confidence threshold
β, a fine-tuned BERT model (bert-base-uncasedfrom
HuggingFace Transformers) provides secondary classification.
The posterior is computed using Bayes theorem:
P(suspicious|text) = P(text|suspicious)·P(suspicious)

When this posterior falls belowβ= 0.65, the BERT model is
invoked to reduce misclassification risk on ambiguous inputs.
The BERT model processes the raw justification text through
12 transformer layers and produces a binary classification with
its own confidence score. If both models disagree, the higher-
confidence prediction is selected.
The training data consists of 2,000 synthetic justification
samples representing both legitimate and suspicious request
patterns, with a 60-40 split. Legitimate samples include spe-
cific project references and deadline mentions. Suspicious
samples contain vague phrasing, urgency without specificity,
and patterns associated with social engineering. Based on
published benchmarks for TF-IDF + Naive Bayes text clas-
sification in security-adjacent domains, the primary classifier
is to achieve approx 83% accuracy, with precision of∼0.81
and recall of∼0.85for the suspicious class. BERT fallback is
expected to raise combined accuracy to approx 89%.
D. LLM-Assisted Voting-Based Authorization

module flags the justification, the system escalates the access
request to human reviewers. Rather than routing all requests
to a generic admin pool, the framework uses an LLM to select
appropriate reviewers. The LLM analyzes the resource type,
sensitivity classification, requesting users department, and or-
ganizational hierarchy to identify individuals best positioned
to evaluate the request.
Selected reviewers receives a decision packet which con-
tains the requester identity, target resource, computed risk
score, relevant anomaly indicators, NLP assessment of the
justification, and a summary of recent access history. Each
reviewer casts a vote through dashboard. The system applies
weighted majority voting:

E. Blockchain-Based Audit and Trust Mechanism
The framework records every significant event as a block
in a permissioned blockchain. Each blockB i contains event
data, timestamp, and SHA-256 hash of the preceding block:
Hi =SHA-256(uid∥ts∥event∥score∥action∥Hi−1)(9)
Bi ={D i, Ti, Hi−1, Hi}(10)
Events recorded event includes successful and failed login
attempts, risk scores with feature breakdowns, access request
submissions, NLP classification results, individual votes with
timestamps, final decisions, smart contract creation, and access
revocations. Any modification to blockB j (wherej < i)
produces differentH j, causing a mismatch in all subsequent
blocks that can is easily detected through a linear-time chain
verification scan.
For access grants approved through voting, smart contracts
is created which encode the access policy by granted resource,
permission scope, duration, and conditional constraints. Upon
expiry or any constraint violates, the contract triggers auto-
matic revoke. This eliminates the well documented problem
of temporary permissions persisting.
The blockchain is implemented as a lightweight permis-
sioned chain, avoiding the computational overhead of proof-
of-work consensus while retaining the integrity needed for
enterprise audit compliance.
F . Threat Model and Security Assumptions
The framework addresses the following primary adversarial
scenarios:
•Credential theft:Detected through contextual mismatch
between the attacker’s access patterns and the legitimate
user’s baseline.
•Insider threats:Mitigated by routing unusual access
requests through voting.
•Privilege escalation:Made traceable through the
blockchain audit trail.
•Log tampering:Prevented by hash-chain integrity veri-
fication.

V. EXPECTEDSYSTEMBEHAVIOR
The framework is at the design and architectural validation
stage. This section presents expected performance derived
from design specifications and published benchmarks of in-
dividually comparable components.
A. Risk Scoring Performance
Based on accuracy ranges reported by Wiefling et al. [3],
Picard and Pierre [9], and Fereidouni et al. [10], the risk
scoring model is projected to achieve 85–92% accuracy on
adequately representative datasets. The expected false positive
rate is moderate, concentrated on first-time device and location
combinations that lack an established baseline.
B. NLP Classification Performance
The TF-IDF + Naive bayes classifier is projected to achieve
approx 83% overall accuracy, with precision of∼0.81and
recall of∼0.85for the suspicious class. Activation of the
BERT fallback for posterior probabilities belowβ= 0.65is
expected to raise combined accuracy to∼89%.

to be below 500ms per event, acceptable given that logging

B. Limitations
Several limitations warrant acknowledgment. The frame-
work has not been implemented in a production environment;
performance projections are derived from published bench-
marks and require empirical validation. ML model perfor-
mance is contingent on training data quality; models trained on
narrow datasets may exhibit blind spots. The blockchain layer
introduces storage overhead. The voting mechanism introduces
latency. The current design evaluates risk at two discrete
points (login and resource request) rather than continuously
during sessions. The honeypot module adds infrastructure
complexity and requires careful network isolation to avoid
creating new attack surfaces. Behavioral monitoring raises
privacy concerns that any deployment must address through
consent mechanisms and data minimization practices [21].

C. Comparison with Existing Approaches
Compared to standalone RBA systems [3], [9], the proposed
framework extends adaptive authentication to resource-level
authorization and adds deception-based threat intelligence.
Compared to blockchain access control systems [16], [18],
it introduces context-aware decision-making and adaptive risk
scoring. Compared to LLMAC [19], it includes quantitative
risk scoring, a voting governance mechanism, an immutable
audit trail, and a honeypot layer for stolen credential scenarios.
The proposed framework is, to the best of our knowledge, the
first to unify all five capabilities.
VII. CONCLUSION ANDFUTUREWORK
This paper proposed a framework for adaptive identity
and access management integrating machine learning, large
language models, blockchain technology, and honeypot-based
deception under Zero Trust principles. The paper presented the
complete design, modular architecture, mathematical formula-
tions for risk scoring and anomaly detection, and an expected
performance analysis grounded in published benchmarks. The
honeypot module introduces a proactive dimension to the
framework, converting confirmed stolen-credential attacks into
intelligence-gathering opportunities rather than simply block-
ing them.
Future work includes: implementation of the proposed
framework followed by empirical validation on realistic
datasets; integration of SHAP-based explainable AI for trans-
parent risk decision attribution; enhancing the honeypot with
LLM-generated synthetic documents to make the deception
harder for sophisticated attackers to detect; continuous session-
level authentication using behavioral biometrics [11], [12];
migration of the blockchain to a distributed permissioned
network; incorporation of federated learning for privacy-
preserving behavioral profile construction [20], [21]; and inte-
gration with enterprise IAM platforms such as Keycloak [22].
A longer-term direction involves extending the LLM com-
ponent from voter selection to automatic security policy trans-
lation, where the model reads organizational policy documents
and generates enforceable access control rules while flagging
contradictions and ambiguities.
